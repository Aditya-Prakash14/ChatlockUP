# .gitignore Configuration Guide

This document explains what files are ignored in the ChatlockUP repository and why.

## Root `.gitignore` (/.gitignore)

The root `.gitignore` provides project-wide rules for ignoring files and directories across both server and client.

### Categories

#### Dependencies
```
node_modules/    # Package dependencies (installed via npm)
.pnp             # Yarn Plug'n'Play cache
.pnp.js          # Yarn Plug'n'Play manifest
```

#### Build & Distribution
```
build/           # Compiled/bundled output
dist/            # Distribution files
.next/           # Next.js build output
out/             # Build output
client/build/    # React build directory
server/dist/     # Server distribution
```

#### Environment Variables (CRITICAL - DO NOT COMMIT)
```
.env                  # Main environment variables
.env.local           # Local overrides
.env.development.*   # Development-specific
.env.test.*          # Test environment
.env.production.*    # Production settings
.env.*.local         # Any local variants
server/.env          # Server-specific config
client/.env          # Client-specific config
```

#### Prisma
```
server/prisma/migrations/*    # Database migrations (auto-generated)
server/generated/              # Prisma generated client
.prisma/                       # Prisma cache
```

#### Logs & Testing
```
logs/                   # Log files
*.log                   # Any log file
npm-debug.log*         # NPM debug logs
yarn-error.log*        # Yarn error logs
/coverage              # Test coverage reports
*.lcov                 # Coverage data
.nyc_output            # Istanbul coverage output
```

#### OS Files
```
.DS_Store              # macOS system files
Thumbs.db             # Windows image cache
desktop.ini           # Windows folder config
```

#### IDE & Editors
```
.vscode/              # VS Code settings
.idea/                # JetBrains IDE settings
*.sublime-workspace   # Sublime Text workspace
*.swp                 # Vim swap files
*~                    # Backup files
```

#### Security
```
.ssh/                 # SSH keys
*.pem                 # Private key files
*.key                 # Cryptographic keys
*.crt                 # Certificates
*.cert                # Certificates
private_keys/         # Private key directory
secrets/              # Secret directory
```

#### Miscellaneous
```
.npm                  # NPM cache
.eslintcache          # ESLint cache
*.tsbuildinfo         # TypeScript build info
```

## Security Considerations

### 🔐 NEVER COMMIT
- `.env` files with secrets
- Private keys (*.pem, *.key)
- API keys or tokens
- Database passwords
- SSH keys

### ✅ DO COMMIT
- `.env.example` (template without values)
- Source code
- Configuration files (without secrets)
- Documentation

### How to Share Secrets Safely
1. Create `.env.example` with placeholder values
2. Share actual `.env` through secure channel
3. Team members copy `.env.example` → `.env` and fill in values locally

### Example `.env.example`
```bash
# Database
DATABASE_URL=postgresql://user:password@localhost:5432/chatlockup

# JWT
JWT_SECRET=your_secret_key_here

# API
CLIENT_URL=http://localhost:3000
REACT_APP_API_URL=http://localhost:3001
```

## How to Handle Special Cases

### Adding New Ignored Patterns

If you need to ignore new files/directories:

1. **For one folder/file:** Add to relevant `.gitignore`
2. **For entire project:** Add to root `.gitignore`
3. **For IDE only:** Use `.git/info/exclude` (not committed)

### Unignoring a File

If a file is ignored but you need to commit it:

```bash
# Force add an ignored file
git add -f file-to-track.env

# Or update .gitignore to not ignore it
# Remove the pattern from .gitignore
git add .gitignore
git commit -m "chore: stop ignoring specific file"
```

### Checking What's Ignored

```bash
# See if a specific file is ignored
git check-ignore -v path/to/file

# See all ignored files in status
git status --ignored
```

## CI/CD Considerations

### GitHub Actions
The workflows in `.github/workflows/` are NOT ignored because:
- They're essential project configuration
- Team members need to review them
- CI/CD setup should be version-controlled

### Build Artifacts
Build outputs (build/, dist/) are ignored to prevent:
- Large repository size
- Merge conflicts
- Outdated artifacts
- CI/CD redundancy

## Performance Tips

### Large Files
If you have large files (binaries, data):
1. Consider `git lfs` (Large File Storage)
2. Or host externally and reference

### Repository Cleanup
```bash
# Remove accidentally committed ignored files
git rm --cached node_modules -r
git commit -m "chore: remove accidentally committed node_modules"

# Force push only if on personal branch (NOT main)
git push origin branch-name --force-with-lease
```

## Common Mistakes to Avoid

❌ **DON'T:**
- Commit `.env` with secrets
- Commit `node_modules/`
- Commit build output
- Commit IDE configuration as project settings
- Use `git add -f` to bypass .gitignore carelessly

✅ **DO:**
- Use `.env.example` for templates
- Let `.gitignore` handle dependencies
- Regenerate build output in CI/CD
- Document setup steps in README
- Review `.gitignore` before committing

## Verification Checklist

Before pushing code:

- [ ] `.env` files are NOT tracked (check with `git status`)
- [ ] Private keys are NOT in repo
- [ ] `node_modules/` is ignored
- [ ] Build output is ignored
- [ ] IDE files are ignored (except shared `.vscode/settings.json`)
- [ ] `.gitignore` itself is committed
- [ ] No large binary files committed

```bash
# Verify with these commands
git status --ignored              # See all ignored files
git ls-files | grep node_modules  # Should show nothing
git ls-files | grep .env          # Should show nothing
git ls-files | grep .env.example  # Should show only examples
```
